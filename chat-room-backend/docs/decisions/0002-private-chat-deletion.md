# ADR 0002：私聊删除采用“单方清空”

- 状态：已接受
- 日期：2026-07-30
- 范围：阶段 0 产品语义基线

## 背景

当前 `DELETE /api/private-chats/{id}` 会删除双方全部消息，并把共享会话状态设为 `DELETED`。任何一方都能永久清除另一方的聊天记录，而且已有已读回执时还可能被外键阻止。

## 决策

普通“删除会话”改为只影响当前用户：

1. 删除者看不到清空点之前的消息；
2. 对方的会话列表和历史记录不受影响；
3. 共享消息不会因一方删除而物理删除；
4. 对话收到新消息后，会重新出现在删除者的列表中；
5. `ChatStatus` 只表达双方关系状态，普通删除不再把共享关系改为 `DELETED`；
6. 如以后需要“双方永久销毁”，必须提供独立、明确命名并带二次确认的接口。

## 推荐数据模型

优先使用参与者级状态，例如：

```text
private_chat_members
  private_chat_id
  user_id
  cleared_at
  hidden_at
```

若下一阶段控制改动规模，也可暂时在 `private_chats` 中增加 `user1_cleared_at` 与 `user2_cleared_at`。消息查询必须根据当前用户的清空点过滤。

## 阶段 0 边界

本阶段只冻结产品语义和迁移方向，不改现有表结构，也不执行当前的全局删除接口。模型、接口和前端行为将在后续实现阶段一起调整。
