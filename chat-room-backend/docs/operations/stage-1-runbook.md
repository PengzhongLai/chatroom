# 阶段 1 执行记录

- 执行日期：2026-07-30
- 数据库：本机 MySQL 8.0.43，schema `chat_room`
- 后端：Spring Boot 3.4.4、Java 17
- 前端：Vue 3、Vite

## 1. 本阶段完成范围

阶段 1 处理直接影响账户数据、消息可见性和频道管理的高风险问题：

1. API 不再直接返回 JPA 实体，统一映射为响应 DTO。
2. 密码字段增加序列化兜底保护；当前用户、用户搜索、频道、私聊和消息响应均不包含密码。
3. 消息搜索在数据库查询中同时执行成员身份、私聊参与者和历史消息级别校验。
4. WebSocket 对连接、订阅和发送三个阶段分别鉴权。
5. 文件上传和下载均要求登录，并校验扩展名、声明类型和文件签名。
6. 修复频道角色越权、所有权转让原子性以及历史数据不一致。
7. 关闭 Open Session in View，避免控制器序列化时意外加载实体关系。
8. 移除聊天正文的 `v-html` 渲染，关闭可窃取 Token 的存储型 XSS 路径。

## 2. API 与敏感字段隔离

新增面向客户端的响应模型和集中映射器。控制器及消息、私聊服务返回 DTO，不再把 `User`、`Channel`、`Message` 等实体直接交给 Jackson。

额外防线：

- `User.password` 标记为忽略序列化；
- 被撤回消息只返回系统消息形态，不返回原内容、文件信息和提及列表；
- 频道邀请码只对频道创建者和管理员返回；
- 分页响应使用明确的页码、页大小、总数和内容字段。

前端消息正文使用 Vue 文本插值渲染，@ 提及和搜索关键词通过受控的文本片段与 CSS 类高亮，不再拼接或执行用户提供的 HTML。

## 3. 搜索授权

搜索查询只返回当前用户有权查看的记录：

- 频道消息：必须仍是频道成员；
- `ALL`：可查看全部未撤回消息；
- `NONE`：只能查看加入频道之后的消息；
- `LIMITED`：只能查看频道当前最近指定数量的消息，与现有频道历史加载规则一致；
- 私聊消息：私聊必须为 `ACTIVE`，且当前用户必须是参与者；
- 搜索关键词中的 `%`、`_` 和转义字符按普通字符处理；
- `q` 长度限制为 1–100，`size` 限制为 1–100。

权限过滤直接位于数据库查询中，分页总数与结果使用同一授权条件，避免“先查出再在内存中过滤”导致越权和分页侧信道。

## 4. WebSocket 授权

STOMP 拦截器执行以下校验：

- `CONNECT` 必须携带有效 JWT，且 Token 对应用户仍存在；
- Principal 固定使用服务端解析出的用户 ID，不信任客户端自报身份；
- 订阅频道主题前校验频道成员身份；
- 用户队列只能订阅当前 Principal 对应的目标；
- 频道消息和私聊消息发送前再次校验成员或参与者身份；
- 拒绝向 Broker 目标直接发送，并拒绝未知 `/app/*` 目标；
- WebSocket 跨域来源由 `WEBSOCKET_ALLOWED_ORIGINS` 配置。

当前简单 Broker 不会在用户被踢出频道后主动撤销已经建立的旧订阅；服务端会阻止其后续发送，但“立即取消现有订阅”需要在后续阶段增加会话驱逐机制。

## 5. 文件上传与下载

后端不再暴露匿名静态文件目录。`/api/files/upload` 和 `/files/{storedName}` 均经过 JWT 安全链。

上传处理：

- 使用 UUID 生成服务端文件名；
- 拒绝路径穿越和非规范下载名称；
- 同时检查扩展名、客户端 MIME 和文件魔数；
- 拒绝 HTML、SVG 等主动内容；
- 允许受控的图片、PDF、Office 文档、文本和常见压缩包类型。

下载处理：

- 返回安全的 `Content-Disposition`；
- 添加 `nosniff`、沙箱 CSP、私有缓存和同站资源策略；
- 前端图片预览和文件下载统一以 Bearer Token 请求 Blob，不使用匿名文件直链。

阶段 1 的附件授权粒度是“任意已登录用户”。要实现频道成员或私聊双方级别的下载授权，后续需要为附件建立独立记录并关联消息。

## 6. 频道角色与所有权

`channels.creator_id` 是频道所有权的唯一权威字段，`channel_members.role=CREATOR` 作为一致性镜像。

代码修复：

- 创建者权限统一根据 `channel.creator.id` 判断；
- 普通角色更新接口不能写入 `CREATOR`；
- 管理员只能踢出普通成员，不能踢出创建者或其他管理员；
- 只有创建者能提升、降级管理员、转让或删除频道；
- 转让、删除、退出、提升和降级操作锁定频道行；
- 所有权转让在一个事务内更新权威创建者、旧创建者角色和新创建者角色；
- 转让前后校验恰好存在一个 `CREATOR` 镜像。
