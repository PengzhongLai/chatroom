# 阶段 2 执行记录

- 执行日期：2026-08-01
- 范围：请求 DTO、Bean Validation、统一异常和分页边界
- 兼容性原则：保留现有前端 JSON 字段、成功响应结构和默认分页大小

## 1. 请求 DTO

REST 控制器不再使用 `Map` 接收请求体。新增的强类型请求模型覆盖：

- 注册、登录；
- 创建和更新频道；
- 邀请码加入、成员邀请、踢人、转让、提升和降级；
- 发起私聊；
- 用户在线状态和主题；
- 频道列表、用户搜索、消息搜索和消息分页。

STOMP 消息也改为请求 DTO，覆盖频道消息、私聊消息、输入状态、已读和撤回。客户端提交的字段无法再通过不安全的类型转换进入业务层。

## 2. Bean Validation 规则

核心边界包括：

- 用户名长度 3–50，只允许字母、数字和下划线；
- 密码长度 6–100；
- 频道名称非空且最多 100 个字符，描述最多 255 个字符；
- 数据库 ID 必须为正数；
- 邀请码最多 20 个字符；
- `LIMITED` 历史模式必须提供 1–1000 的历史消息条数；
- 用户状态使用枚举，主题只允许 `dark` 或 `light`；
- 搜索词不能为空，消息搜索最多 100 个字符，用户搜索最多 50 个字符；
- 消息正文最多 4000 个字符，文件名最多 255 个字符，文件路径最多 500 个字符；
- 附件消息只能引用服务端生成的规范 `/files/{uuid}.{ext}` 路径；
- 文本消息必须包含非空正文，附件消息必须包含文件名和路径；
- 客户端不能伪造 `SYSTEM` 消息。

控制器负责第一层 Bean Validation，服务层仍对分页、登录状态、权限和关键业务状态做防御性检查。

## 3. 统一异常语义

新增 `BusinessException` 和 `ErrorCode`，业务层不再使用通用 `RuntimeException` 表示预期失败。

| HTTP 状态 | 使用场景 |
|---:|---|
| 400 | 参数错误、邀请码无效、非法业务输入 |
| 401 | 用户名或密码错误、登录身份失效 |
| 403 | 非频道成员、非管理员、非私聊参与者 |
| 404 | 频道、用户、私聊或消息不存在 |
| 405 | 请求方法不受支持 |
| 409 | 重复用户名、重复频道名、成员或状态冲突 |
| 413 | 上传文件超过 50MB |
| 415 | 不支持的请求内容类型 |
| 500 | 未预期的服务器错误和文件处理错误 |

参数校验失败响应增加 `errors` 字段，例如：

```json
{
  "code": 400,
  "message": "用户名不能为空",
  "data": null,
  "errors": {
    "username": "用户名不能为空",
    "password": "密码不能为空"
  }
}
```

未预期异常只向客户端返回“服务器内部错误”，详细堆栈只写入服务端日志，避免泄露数据库地址、文件路径或实现细节。数据库唯一约束冲突统一返回 409。

WebSocket 控制器通过 `/user/queue/errors` 返回相同的 `type=ERROR`、HTTP 语义码和安全消息。

## 4. 分页和查询上限

统一分页规则：

- `page`：0–10000；
- `size`：1–100；
- 普通列表默认 `size=20`；
- 消息历史默认 `size=50`。

频道列表、频道消息、私聊消息和消息搜索均使用统一分页模型，并在业务层再次校验。用户搜索改为数据库层固定最多返回 10 条，不再先读取所有匹配用户后在内存截断。

现有响应形状保持不变，因此前端的频道列表、消息滚动加载和搜索逻辑无需改写。

## 5. 额外一致性修复

- HTTP 撤回接口现在同时校验 URL 中的频道 ID 与消息实际所属频道，不能借频道接口撤回私聊或其他频道消息；
- 频道改名使用“名称相同且 ID 不同”的冲突检查，允许对当前频道做合法更新；
- 非 `LIMITED` 历史模式会丢弃无意义的 `historyLimit`，避免脏配置；
- 前端 `ApiResponse` 类型增加可选的字段级 `errors` 定义。
